# Sotto

macOS 原生微信阅读助手，支持群聊和私聊。读取本人微信已同步的本地记录，把选定会话和时间范围交给兼容 Chat Completions 的模型问答。

当前版本：**0.0.1 build 3**。Sotto 作为菜单栏工具运行，不显示 Dock 图标或 Command+Tab 入口，也没有独立聊天主窗口。聊天操作只在微信窗口旁的气泡和浮窗中完成。验证记录见 `docs/verification-0.0.1-build3/readiness.json`。

> 开发阶段版本固定为 **0.0.1**；构建号只用于区分本机构建，不代表稳定发布或功能版本。

## 安装

推荐使用 `artifacts/Sotto-0.0.1-arm64.dmg`：

1. 双击 DMG，把「Sotto.app」拖入「Applications」。
2. 从「应用程序」打开。启动后通过微信窗口旁的气泡或菜单栏 Sotto 图标使用。
3. 首次连接微信时按应用内提示授予“完全磁盘访问”（读取本地数据库）和“辅助功能”（跟随窗口标题）。

本构建使用本机自签名身份，**没有 Apple Developer ID，也没有公证**。在其他 Mac 上首次打开时，系统可能提示“无法验证开发者”：请在 Finder 中右键应用选择“打开”，或到“系统设置 → 隐私与安全性”中允许打开；不要关闭 Gatekeeper 或 SIP。更新应用后，如系统重新询问权限，请在系统设置中移除旧条目，再重新添加当前「Sotto.app」并授权。

当前构建为 arm64、macOS 27；`LSMinimumSystemVersion` 为 27.0。

## 从旧版升级

Sotto 的 bundle identifier 是 `moe.tachyon.sotto`，与旧的 `cn.local.ChatFloat` 不同。首次启动 Sotto 时会把旧应用支持目录（模型配置、逐库密钥、导入缓存）复制到新目录，并迁移常用偏好；旧目录不会删除，可继续保留旧版应用作回退。

由于 bundle identifier 和签名身份都变了，系统会把 Sotto 视为新的应用：**完全磁盘访问和辅助功能权限需要重新授予**；旧应用的权限条目不会被 Sotto 继承，也不会自动删除。

## 使用方式

- 启动后不弹出聊天主窗口；微信聊天窗口旁显示气泡，点击展开面板。菜单栏 Sotto 图标提供打开伴读、连接、设置和退出入口。
- 选择会话、时间范围、提问和回看回答均在气泡展开的浮窗中完成；连接、设置和原消息使用明确打开的辅助窗口。没有微信聊天窗口时不会退回独立聊天主窗口。
- 点回微信、切换应用或切换微信窗口会收起面板；图片等非聊天窗口不显示气泡。
- 群聊和私聊统一出现在会话选择器中。列表只包含本地消息表中确有记录的会话，不把仅有共同群的成员资料当作私聊。
- 从“更多 → 已保存导入”重新选择导入记录时，会自动采用该记录自身的时间跨度；导入记录不支持自动跟随，需使用固定范围。
- 会话自动识别，无需开关。微信自身的独立聊天窗口能唯一确认会话时直接跟随，精确保留 emoji、空格和标点；无法确认时提示“选择会话”，选择后才能提问。手选只用于当前微信窗口，切换窗口会重新识别；之后遇到可识别窗口会自动跟随。**微信主窗口内部切换聊天仍须重新手选**。正式应用不含截图/OCR、不需要屏幕录制，也不读取微信运行内存。
- **Return 发送；⌘Return 或 ⇧Return 换行。** 输入法候选优先确认，多行粘贴保留。生成中可以编辑下一条草稿，不能重复提交。
- 输入框、设置输入项和可选中的回答文字使用 macOS 标准编辑命令；支持 ⌘A 全选、⌘C 复制、⌘V 粘贴、⌘X 剪切、⌘Z 撤销和 ⇧⌘Z 重做。
- **新对话**清空当前会话的 AI 回答、草稿、上下文和参考快照；生成中使用会先取消当前请求。会话、时间范围和连接配置保留，不删除微信记录；切走再返回不会恢复被清空的内容。
- 当前进程内按会话保留回答与草稿，收起不清空。退出或重启前请复制需要长期保存的内容。

输入法使用 macOS 原生文本编辑器与候选窗口。正式运行和合成检查使用相同的菜单栏 accessory 策略，避免浮窗移动到微信所在桌面后，候选窗口仍留在旧桌面。Return 在中文组合输入期间先交给输入法，不发送问题。

## 连接与模型

已有本机密钥时自动连接，暂时失败只做有限重试。首次配置在连接页完成账号选择，并通过“高级与诊断”导入逐库密钥清单。初次建立读取权限的流程另有明确说明与确认；本助手不会自动操作微信或重新取钥。

在“外观与设置 → AI 服务 → 服务配置”中填写完整接口地址、模型名称和 API Key，并明确允许将所选记录发送到该服务。服务若本身不要求密钥可留空。“保存并测试（无聊天）”只验证模型服务，不发送聊天记录。

模型回答支持 SSE 流式输出，可停止生成；失败或中断保留已收到的文字，首段前停止会恢复提问。也支持返回普通 JSON 的服务，此时响应一次显示。Markdown 支持标题、强调、列表、引用、代码和表格；代码可复制，不执行 HTML 或加载远程图片。

时间范围包括 15/30 分钟、1/3/5/12 小时、1/3/7 天和自定义。首问按当时范围读取快照，追问沿用快照；**“刷新记录”只丢弃当前快照并保留下方已有回答**，下一次提问重新读取；**“新对话”才清空回答与上下文**。没有静默截断聊天记录或自动多轮摘要；超出模型容量时需缩短范围或更换模型。

## 外观与数据

外观可选“跟随系统”“浅色”“深色”。跟随系统指跟随 Mac 外观；微信也跟随系统时两者同步，微信单独设置主题时可手动选择匹配外观。

数据库与模型密钥使用**本机普通文件**，目录为 `~/Library/Application Support/moe.tachyon.sotto/credentials`，目录权限 `0700`、文件权限 `0600`。文件不额外加密；能访问当前 Mac 用户文件的程序也可能读到它们。应用不使用钥匙串，不提供旧钥匙串迁移、兼容或回退逻辑，不会为读取密钥请求系统认证。初次使用在应用内填写或导入所需密钥。

账号之间、模型服务之间的密钥分别保存；文件原子替换，删除一项不影响其他项。清理导入记录不删除连接密钥。配置、密钥、聊天记录和构建私钥均不进入源码或应用分发包。

微信数据库访问仍需“完全磁盘访问”，浮窗定位和窗口标题跟随仍需辅助功能权限。这两项系统权限与密钥存储分开管理。

## 消息与图片

支持普通文字、图片、引用回复、卡片/链接及合并转发内可读文字。引用和转发带独立来源标记，不当作当前发送者的新发言；不跨群或超出范围寻找引用来源。语音、表情、系统消息及无法解析的类型计入略过数，不做语音转写。

“允许发送图片”默认关闭。开启后仅准备所选会话与范围内的本地附件，支持普通图片、旧式 XOR DAT 和可从本机元数据获得密钥的 V2 DAT。原图缺失时可退回可解码缩略图，并说明缺失或缩略图状态。

图片最长边缩至 1536 像素后附入多模态请求；默认总预算 20 MB，可调 1–100 MB。单个本地文件读取上限 40 MB，批量读取预算最高 400 MB。未附上的图片有计数与原因，不阻断文字问答。

## 开发与构建

- `Sources/SottoCore`：时间快照、模型请求、凭据文件、导入与 Markdown 数据。
- `Sources/Sotto`：AppKit/SwiftUI 浮窗、窗口跟随和数据库连接。独立聊天窗口仅用于显式开发检查。
- `Backend`：SQLCipher 只读查询与图片解码。
- `Checks`、应用内显式检查参数：合成测试，正式界面没有模拟对话入口。
- `Resources/AppIcon.icns`：应用图标；`scripts/make-icon.py` 可重新生成。
- `artifacts`：当前 0.0.1 App、DMG、源码包及 `SHA256.json`。
- `work`、`.build`：本机中间产物，不分发。

构建使用 Command Line Tools、SwiftPM、Python，以及 Homebrew 的 sqlcipher、zstd、openssl@4；脚本把所需动态库放入应用，不要求安装完整 Xcode。

固定的本机签名材料独立保存在 `~/Library/Application Support/moe.tachyon.sotto.build-signing`。初次创建后，构建只复用它；身份缺失或不一致会停止，不能自动换证书或退回临时签名。它用于本机开发更新的身份连续性，不能替代公开分发所需的 Apple Developer ID 与公证。

```sh
./scripts/check.sh
# 仅首次建立本机构建身份；已建立时不要重复执行：
python3 scripts/local-signing.py setup
python3 scripts/local-signing.py check
# 之后每次构建只复用现有身份：
./scripts/build-app.sh
./scripts/build-dmg.sh
```

`build-app.sh` 在临时目录完成签名和验证后才替换输出，失败或可处理的中断会保留旧包。`build-dmg.sh` 生成带 Applications 快捷方式的标准拖拽安装 DMG，并用同一本机身份签名 DMG。

未验证/限制：没有 Developer ID 与公证；本轮不操作微信，也不向真实模型发送聊天。跟随、窗口和输入验证使用隔离的合成数据或自有宿主，微信中的最终使用效果仍需手动复核。详见 `docs/verification-0.0.1-build3/readiness.json`。
