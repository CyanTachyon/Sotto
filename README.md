# Sotto

Sotto 是 macOS 原生微信阅读助手。它读取本人微信已同步到这台 Mac 的群聊和私聊记录，将你选定的会话、时间范围和问题交给兼容 Chat Completions 的模型，帮助整理重点、查找信息和继续追问。回答可通过“查看参考记录”核对原消息。

Sotto 作为菜单栏工具运行，在微信聊天窗口旁显示气泡，点击后展开浮窗；没有 Dock 图标、Command+Tab 入口或独立聊天主窗口。应用标识为 `moe.tachyon.sotto`。

## 下载与安装

当前版本为 **0.0.4（build 7）**，面向 **Apple Silicon（arm64）、macOS 26.0 及以上**。

1. 从 [v0.0.4 发布页](https://github.com/CyanTachyon/Sotto/releases/tag/v0.0.4) 下载 `Sotto-0.0.4-arm64.dmg`。
2. 打开 DMG，将「Sotto.app」拖入「Applications」，再从「应用程序」启动。
3. 通过菜单栏 Sotto 图标打开连接与设置；微信聊天窗口可用时，也可点击窗口旁的气泡。

**此版本使用本机自签名，没有 Apple Developer ID 签名或 Apple 公证。** macOS 可能显示开发者无法验证等警告，或阻止应用启动。请先核对下载来源，再按 macOS“系统设置 → 隐私与安全性”提供的方式决定是否允许打开；不要关闭 Gatekeeper 或 SIP。

本地数据库读取依赖 `/usr/bin/python3`；首次连接密钥初始化还依赖 Command Line Tools 提供的 LLDB。若本机缺少相应工具，需要先安装。发布包带有所需的 SQLCipher、Zstandard 和 OpenSSL 动态库，使用发布包无需自行安装 Homebrew 依赖。

## 应用内更新

从 0.0.4 起，可在菜单栏或“外观与设置 → 软件更新”中点击“检查更新…”，从本项目的 GitHub Releases 获取新版本。也可开启“自动检查新版本”；默认关闭，仅检查，不自动下载安装。发现新版时菜单栏会显示提示，点击后查看更新说明并决定是否下载、重启安装。

更新列表和安装包均使用内置公钥校验 Ed25519 签名，下载包在解压前验证。更新检查不发送聊天记录、模型 API Key 或数据库密钥，不启用 Sparkle 的系统统计上传；请求仍会由 GitHub 按其服务规则处理。

安装需要退出并重新打开 Sotto。生成回答或初始化连接时不允许安装；任意会话中存在回答或草稿时，会先提醒保存并要求明确确认。更新不会将这些内容改为落盘存储。账号和配置保留；安装目录没有写入权限时，系统可能要求授权。应用仍为本机自签名，自动更新不能代替 Developer ID 签名或公证，也不能保证跨设备的系统权限连续性。

**0.0.3 及更早版本没有更新器，需要先手动安装一次 0.0.4 或更新版本。** 请从 Applications 中运行，避免直接从只读 DMG 启动。

## 首次使用

首次连接需要准备本地数据访问权限、**所选账号各数据库对应的密钥**，以及你自己的模型服务配置；安装后不会自动获得这些条件。

### 连接微信

1. 在连接页检测并选择本人微信账号。按应用提示为当前「Sotto.app」授予“完全磁盘访问”，用于读取本地数据库；授予“辅助功能”，用于定位微信窗口、读取窗口标题并跟随会话。无需屏幕录制权限。
2. 如果已有逐库密钥，在“高级与诊断 → 导入已有逐库密钥…”中导入 JSON 清单。清单外层为 `keys`，每项以 `db_storage` 下数据库的相对路径为键，值包含 64 位十六进制的 `enc_key`。单独一把表情库密钥不能代替聊天分库密钥；缺少相关数据库密钥时无法完成对应读取。
3. 验证连接。已有有效本机密钥时，之后启动会尝试自动连接；暂时失败仅做有限次数重试。

没有可用密钥时，连接页提供需要你明确确认的“一次性初始化”：先自行正常退出微信，Sotto 再创建、重新签名并启动临时微信副本，通过调试读取并验证所选账号的数据库密钥。原版应用与 SIP 保持不变，但副本会访问本人账号资料，可能要求手机确认或重新登录，也可能由微信更新缓存或登录状态。结束后需自行打开原版微信并验证连接。

**这条首次取钥路线尚未完成真实账号验证，不能保证成功。** 当前流程限定 Apple Silicon 与微信 **4.1.15**，需要系统允许调试；失败时不会自动降低安全设置。正常伴读读取本地数据库，不进行截图或 OCR；上述经确认的首次取钥流程另行使用调试能力。

### 配置模型服务

在“外观与设置 → AI 服务 → 服务配置”填写完整 Chat Completions 接口地址、模型名称和 API Key，并明确允许将所选记录、已开启的图片和问题发送到该服务。远程服务要求 HTTPS；HTTP 仅允许本机地址。服务本身不要求密钥时可留空。

“保存并测试（无聊天）”只测试服务连通性，不发送聊天记录。模型服务由你选择和提供；服务可能保存请求，请依据该服务的数据处理规则决定是否发送。

### 导入聊天文件

也可通过浮窗中的“更多 → 导入聊天记录…”使用自行准备的记录，无需先解密微信数据库；模型问答仍需完成服务配置。导入支持 UTF-8 JSON 或三列 TAB 文本，单文件不超过 5 MB，时间必须包含日期和时区。

JSON 示例（虚构内容）：

```json
{
  "conversation": "项目讨论",
  "messages": [
    {
      "timestamp": "2026-10-19T09:00:00+08:00",
      "sender": "小林",
      "text": "今天下午三点讨论发布计划。"
    }
  ]
}
```

文本第一行须为 `# 会话: 项目讨论`，之后每行按“ISO 8601 时间、发言者、正文”排列，用 TAB 分隔。从“更多”菜单重新选择已保存的导入时，会采用该记录自身的时间跨度；导入记录是独立数据源，不自动跟随微信窗口。

## 日常使用

- **会话跟随**：微信独立聊天窗口能唯一确认会话时自动跟随，保留名称中的 emoji、空格和标点；无法确认时需手动选择。手选仅作用于当前微信窗口，切换窗口后重新识别；识别到可确认的独立聊天窗口时会恢复自动跟随。**在微信主窗口内部切换聊天后，必须重新手选会话。**
- **气泡位置**：按住气泡拖动可调整位置，整个气泡会保持在所属微信窗口的可见区域内，并避开顶部标题栏。各窗口在本次运行中分别记住相对位置，窗口移动或缩放后重新约束；退出后不保留。拖动松开不会打开面板。
- **窗口行为**：点击气泡展开面板，点回微信、切换应用或切换微信窗口时收起。图片等非聊天窗口不显示气泡；没有可用微信聊天窗口时不会打开独立聊天主窗口。连接、设置和原消息查看使用辅助窗口。
- **提问与编辑**：Return 发送，⌘Return 或 ⇧Return 换行；输入法组合输入期间先确认候选。支持多行粘贴和 macOS 标准复制、粘贴、撤销等操作。生成中可编辑下一条草稿，不能重复提交。
- **回答**：支持 SSE 流式输出和普通 JSON 响应，可停止生成。失败或中断保留已经收到的内容，首段文字前停止会恢复问题。支持 Markdown 标题、强调、列表、引用、代码和表格；代码可复制，不执行 HTML 或加载远程图片。
- **时间与快照**：可选 15/30 分钟、1/3/5/12 小时、1/3/7 天或自定义范围。首问读取并固定当时的记录快照，追问沿用该快照。“刷新记录”保留已有回答，下次提问重新读取，旧快照的问答不再作为新快照的上下文。“新对话”清空当前会话的回答、草稿、上下文和参考快照，不删除微信记录。
- **会话状态**：回答与草稿按会话保留在当前进程中，收起面板不会清除；退出或重启后不保留，请提前复制需要长期保存的内容。
- **外观**：可跟随系统，或手动选择浅色、深色。微信单独设置主题时，可手动选择匹配外观。

会话列表只展示本地消息表中有记录的群聊或私聊，不把联系人资料误当作已存在的私聊。本地记录不等于云端完整历史；Sotto 不静默截断聊天记录或自动多轮摘要，超出模型容量时需缩短范围或调整模型。

## 消息与图片

支持普通文字、图片、引用回复、卡片/链接及合并转发中的可读文字。引用和转发有独立来源标记，不当作当前发送者的新发言；不跨会话或超出所选范围寻找引用来源。语音、表情、系统消息及无法解析的类型计入略过数，不做语音转写。

“允许发送图片”默认关闭。开启后只准备所选会话和范围中的本地附件，支持普通图片、旧式 XOR DAT，以及能从本机元数据获得匹配密钥的 V2 DAT。原图缺失时可使用可解码的缩略图，并提示缺失或缩略图状态；不支持的格式会显示原因。

图片最长边缩至 1536 像素后附入多模态请求。默认总预算 20 MB，可调 1–100 MB；单个本地文件读取上限 40 MB，批量读取预算最高 400 MB。无法附上的图片有计数与原因，不阻断文字问答。

## 隐私与本地存储

- 只有在你允许目标服务并发起提问后，才将**所选会话与时间范围的快照**、问题、同一快照的后续问答，以及明确开启的图片发送给所配置服务。不会把数据库密钥或完整数据库发送给模型服务。
- 从微信数据库读取的正文、AI 回答和草稿仅保留在进程内存；主动导入的聊天文件内容会缓存到本机，可在设置中清理。
- 数据库密钥和模型 API Key 保存在 `~/Library/Application Support/moe.tachyon.sotto/credentials` 下的**普通文件**中：目录权限为 `0700`，文件权限为 `0600`，**没有额外加密，也不使用系统钥匙串**。可访问当前 Mac 用户文件的程序仍可能读取它们。
- 不同账号和模型服务的密钥分别保存，可在应用内删除；清理导入缓存不删除连接密钥。完全磁盘访问、辅助功能权限由 macOS 单独管理。

## 开发与构建

主要目录：`Sources/SottoCore` 为快照、模型请求、凭据与导入逻辑；`Sources/Sotto` 为 AppKit/SwiftUI 界面、窗口跟随与连接；`Backend` 为 SQLCipher 只读查询与图片解码；`Checks` 和显式检查入口使用合成数据。正式界面不提供模拟对话入口。

构建需要 macOS 26 或更新的 SDK、Command Line Tools、SwiftPM、Python 3，以及系统的 make、Perl 和 Tcl。依赖脚本从固定版本的官方源码构建 SQLCipher、Zstandard、OpenSSL，统一以 arm64、macOS 26.0 为目标；不会直接复制随本机系统升级的 Homebrew 二进制。不要求安装完整 Xcode。首次构建需要联网下载依赖，也可通过 `SOTTO_DEPENDENCY_SOURCES` 指定已有的三份源码归档目录。

0.0.4 源码构建使用 SQLCipher 4.19.0、Zstandard（zstd）1.5.7、OpenSSL 4.0.2，以及固定为 2.10.0 的 Sparkle 官方 SwiftPM 二进制发行包。前三者从源码构建；Sparkle 的下载由 SwiftPM 按固定校验值验证，打包时保留链接和权限、精简为 arm64，并使用原有本机身份签名。依赖源码及 Sparkle 对应的发行构建输入随同一 [Release](https://github.com/CyanTachyon/Sotto/releases/tag/v0.0.4) 的 `Sotto-0.0.4-dependency-sources.zip` 提供，详见 [ThirdParty/NOTICES.md](ThirdParty/NOTICES.md)。

```sh
./scripts/check.sh
# 首次建立此 Mac 的本机构建签名身份
python3 scripts/local-signing.py setup
python3 scripts/local-signing.py check
./scripts/build-app.sh
python3 scripts/check-compatibility.py artifacts/Sotto.app
./scripts/build-dmg.sh
```

可用 `SDKROOT` 指定 SDK；本次发布使用 macOS 26.5 SDK、最低目标 26.0。构建脚本会核验主程序及全部随包动态库的架构、最低系统版本与依赖路径，拒绝混入要求更高系统版本的库。依赖默认缓存在 `.build/macos26-dependencies`。

输出位于本机 `artifacts/`，该目录不作为源码分发内容。`build-app.sh` 在临时目录完成签名与验证后才替换应用；`build-dmg.sh` 创建带 Applications 快捷方式的拖拽安装镜像，已有同名 DMG 时会停止。

本机签名材料保存在 `~/Library/Application Support/moe.tachyon.sotto.build-signing`，请勿提交或分发。创建后构建会复用该身份，缺失或不一致时停止；自签名仅提供本机构建身份连续性，不能代替 Developer ID 或公证。

### 发布自我更新

本项目的生产更新公钥位于 `Resources/UpdatePublicKey.txt`，只允许对应私钥签名的更新。更新私钥与代码签名身份用途不同，不放入仓库或应用，不使用系统钥匙串；仅保存在发布者的 `~/Library/Application Support/moe.tachyon.sotto.update-signing/private-key`（目录 `0700`、文件 `0600`）。保留私钥备份，丢失时不可自动替换现有公钥。

首次建立全新的更新身份时，在尚无公钥和私钥的自有项目中执行 `swift scripts/update-signing.swift setup Resources/UpdatePublicKey.txt`；已有公钥但缺少对应私钥时会停止，不会换钥。Fork 需要设置自己的更新源与新公钥，不能向原项目用户发布更新。普通构建只需要公钥，不读取更新私钥。

发布时先构建、签名并打包完整应用 ZIP，递增 build，再使用官方 Sparkle 2.10.0 发行包中的工具生成签名 feed：

```sh
python3 scripts/prepare-update.py \
  --app artifacts/Sotto.app \
  --archive artifacts/Sotto-0.0.4-macOS-arm64.zip \
  --notes /absolute/path/to/release-notes.txt \
  --output /absolute/path/to/update-output \
  --sparkle-directory /absolute/path/to/Sparkle-2.10.0 \
  --previous-build 6
```

脚本核验应用/ZIP逐文件一致、内置公钥、版本递增、签名和兼容要求；使用文件中的私钥签名，不调用钥匙串。将生成的 `appcast.xml` 与它引用的完整 ZIP 一起上传到同一个 GitHub Release，核对上传哈希后再发布；更新源固定为 `https://github.com/CyanTachyon/Sotto/releases/latest/download/appcast.xml`。**签名后的 XML 不得再编辑**，更新说明直接包含在已签名 feed 内。首次启用后的每个正式 Release 都必须携带正确签名的 `appcast.xml`，否则旧版无法从 latest 地址发现新版。
